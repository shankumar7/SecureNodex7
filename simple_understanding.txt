1. WHAT IS SECURENODEX IN PLAIN ENGLISH?
--------------------------------------------------------------------------------
Normally, when IoT devices (smart meters, sensors, cameras) store data, they 
send it to a single central cloud (like AWS or Google Cloud). 
If that central server gets hacked, leaks data, or goes down, everything fails.

SecureNodeX is a "Zero-Trust, Decentralized IoT Security & Storage Platform":
- Instead of trusting one server, data is encrypted, split into tiny chunks, 
  and scattered across multiple physical computers and edge devices (our 
  Raspberry Pi and teammate laptops).
- Every device has an unforgeable cryptographic hardware identity.
- Every event and device registration is permanently anchored onto an immutable 
  private Blockchain so nobody can falsify history or tamper with logs.


2. THE 3 CORE PILLARS (HOW IT WORKS)
--------------------------------------------------------------------------------
A. DECENTRALIZED DATA STORAGE (SNX-Store):
   - When a file is uploaded, it is encrypted using AES-256-GCM.
   - The encryption key is protected using ECIES (Elliptic Curve Integrated 
     Encryption Scheme over NIST P-256).
   - The file is broken into content-addressed chunks (SHA-256).
   - Chunks are distributed across our cluster: Raspberry Pi, Laptop 2, 3, 4.
   - If one laptop turns off or loses WiFi, the system automatically fetches 
     the surviving replica from another node without failing.

B. HARDWARE IDENTITY & PKI (Zero-Trust):
   - Devices do not use passwords. They use Elliptic Curve Cryptography (ECC) 
     NIST P-256 (secp256r1) keypairs.
   - Each device has an X.509 certificate issued by our internal CA.
   - Communication uses mutual TLS (mTLS) - both client and server prove identity.

C. BLOCKCHAIN AUDIT TRAIL (Chain ID: 20260):
   - We run a private EVM blockchain network.
   - Every file hash, device identity, and tamper alert is logged in our 
     deployed Smart Contracts (AuditLog, IdentityRegistry, DataRegistry).
   - The log forms an immutable Keccak-256 rolling hash chain that can be 
     verified back to the Genesis block.


3. WHERE IS ELLIPTIC CURVE CRYPTOGRAPHY (ECC) USED?
--------------------------------------------------------------------------------
If the jury asks: "Show me where ECC is used":
1. Device Identity & PKI: 
   - Curve: NIST P-256 (secp256r1)
   - Code: pki/ca_core.py
   - Purpose: Hardware private keys and X.509 device certificates.
2. User Authentication (JWT):
   - Curve: NIST P-256 (ES256 ECDSA)
   - Code: backend/app/auth/security.py
   - Purpose: Asymmetric digital signatures on login tokens instead of symmetric secrets.
3. Storage Key Wrapping (ECIES):
   - Curve: NIST P-256 (ECDH key exchange + HKDF)
   - Code: backend/app/storage/crypto.py
   - Purpose: Wraps the AES-256 data key for recipients.
4. Blockchain Transactions:
   - Curve: secp256k1 (EVM standard)
   - Code: backend/app/chain/client.py
   - Purpose: Signs all blockchain transactions (r, s, v signatures).


4. ROLES OF EACH OF THE 4 DEVICES IN YOUR SETUP
--------------------------------------------------------------------------------
- Laptop 1 (Master Controller & Storage Node 1):
  * Runs: Dashboard UI (:3000), Gateway API (:8443), EVM Blockchain (:8545), 
    and local storage daemon (:7443).
  * Coordinates file splitting, Merkle root calculation, and on-chain anchoring.

- Laptop 2 (Teammate Storage Node 2):
  * Runs: Docker storage node (:7443).
  * Holds physical encrypted chunks (AES-256-GCM) on disk.

- Laptop 3 (Teammate Storage Node 3 & Independent Auditor):
  * Runs: Docker storage node (:7443) + auditor inspection CLI.
  * Holds physical encrypted chunks and validates blockchain blocks directly.

- Device 4: Raspberry Pi (Physical IoT Edge Storage Node 4):
  * Runs: snx-storage daemon on port 7443 (`storage/start_pi_node.sh`).
  * Holds real content-addressed chunks on physical SD card storage (`~/storage_data`).

* CLUSTER REDUNDANCY:
  Quorum is configured for N=4, R=3, W=2:
  Every uploaded file is sliced and distributed across 3 of the 4 devices.
  Any single laptop or the Raspberry Pi can disconnect or shut down with 
  ZERO data loss and full download availability!
